# Software Design Principles

ソフトウェア・製品を設計するときに適用する原則。プロジェクト種別を問わない
変更の原則は [PRINCIPLES.md](../PRINCIPLES.md) を参照。

## Development Philosophy
- まず小さなツールを構築する
- ローカルファーストのデザインを優先する
- インフラストラクチャを最小限に保つ

## Design
- 高速なインタラクション
- 最小限のUI

## Architecture
- 最小限の依存関係
- オフライン機能を優先

## CLI Usability

言語・フレームワークによらず、CLIコマンドを実装する場合の最低限のユーザビリティ方針。実装の詳細は言語別のtopicsファイル（Pythonは[PYTHON_CLI.md](python/PYTHON_CLI.md)）を参照。

- **MUST**：`--help` を実装する
- **MUST**：`--version` を実装する
- **SHOULD**：短縮形 `-h`（help）を提供する
- **SHOULD**：version の短縮形は `-V`（大文字）を標準とする。`-v` は verbose 等と衝突しやすいため避ける。フレームワーク・既存慣習と明確に衝突する場合のみ例外とする
- **SHOULD**：少なくとも zsh 向けの shell completion を提供する。bash/fish 等もフレームワーク側で容易に提供できる場合は併せて検討する

## Backup File Naming

ユーザーが設定・データをファイルとして書き出す（エクスポート・バックアップ）機能の、既定ファイル名の規則。アプリ・拡張機能・アドオンの種別を問わず適用する。

- **MUST**：`<アプリ名>-<YYYY-MM-DD>.<拡張子>` とする（例：`steady-loop-2026-07-22.json`、`stick-mark-2026-09-16.zip`）
- **アプリ名**：リポジトリ名から技術スタックの接頭語（`swift-`・`chrome-`・`gwa-` 等）を除いた部分を、小文字のケバブケースで使う（`swift-day-cue` → `day-cue`）。表示名（`DayCue` 等）やキャメルケース、スネークケースは使わない
- **日付**：書き出した時点の、ユーザーのローカル日付をハイフン区切りで付ける（UTC の日付にしない）
- **MUST NOT**：`backup`・`export` などの用途語を名前に足さない（拡張子と保存先で分かる）
- 形式の拡張子は実体に合わせる（設定のみは `.json`、複数ファイルを含む場合は `.zip`）
- ファイル生成を伴わず、画面上にテキスト（JSON）を表示して手動でコピーさせる方式のアプリは、この規則の対象外とする。ファイル名を付けるのはユーザーなので、アプリ名のみ（`log-pair.json`）を目安にする
